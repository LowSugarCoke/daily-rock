🎸 daily-rock · product UI design

Taking the app past the current-song card

Today the app is one screen: fetch the current song, show it, done. The MVP spec (#1) needs five more surfaces before the core loop is real — rate the song you just heard, watch the next one unlock, browse what you've already heard, and let a friend look without an account. This lays out those screens against the app's existing dark theme, using real copy and the actual field names from the backend.

05 · decisions & open questions

What's settled, what still needs a call

Decided
No fraction-style progress bar

The catalog is explicitly unbounded (spec: "must not assume a fixed length"), so the header shows a running count — "Rated: 4" — never "4 of 120".

Decided
Bottom tabs on mobile, top bar past ~768px

Today / History / Share, same three destinations either layout — see the Navigation section above.

Open
Do visitor links show the note text?

Mockup shows notes in the visitor pane since the spec says share = "view the list and history." Worth confirming — notes can get personal.

Open
History: infinite scroll or paged?

Single-owner scale makes infinite scroll simplest to build; paging only matters once the list is very long.

Open
Transition timing

Toast + 500ms cross-fade shown here. Worth trying in-hand before locking the duration — habit-loop feel is a judgment call, not a spec item.

Open
Reorder UI (#5) not mocked yet

Manual catalog reordering/insertion is in scope for the MVP but ships later in the build order — deliberately left out of this pass.
